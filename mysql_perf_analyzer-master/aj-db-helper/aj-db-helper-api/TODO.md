旧系统里面 mysql_perf_analyzer-master/myperf/src/main/java/com/yahoo/dba/perf/myperf/springmvc/StatusController.java 这个状态的逻辑是怎么样的


这个 `StatusController` 主要服务于旧系统的**健康状态总览**：汇总各服务器最近的性能指标，计算变化速率，并给出 Green、Yellow、Red 等状态。

**它不会在每次页面刷新时连接所有 MySQL，而是读取后台扫描器已经采集好的快照。**

整体流程是：

```text
后台定时扫描数据库、系统指标
→ 每台服务器保留前后两次状态快照
→ 页面请求 status.html
→ StatusController 读取快照、计算指标和状态
→ 返回表格 JSON
```

入口在 [StatusController.java](C:/code/ajaxjs/aj/aj-developer-tools/mysql_perf_analyzer-master/myperf/src/main/java/com/yahoo/dba/perf/myperf/springmvc/StatusController.java:30)。

**1. 根据请求参数选择处理方式**

| 参数 | 行为 |
|---|---|
| 不传 `group` | 默认查询所有组 |
| 传 `group` | 只显示指定组 |
| 不传 `host` | 返回多台服务器的最新状态总览 |
| 传 `host` | 转为查询该服务器最近 7 天的历史状态 |

对于受限用户，总览分支还会过滤掉不属于该用户的数据库组。

**2. 每台服务器读取两次采样**

通过 `InstanceStatesManager` 找到服务器状态，再取得：

```java
snaps[0] // 上一次采样
snaps[1] // 最新采样
```

后台每次更新时，会把当前快照移成上一次快照，再保存新快照。这里的比较基准是**相邻两次后台采样**，与我们内存页面“固定基准直到手动重设”的逻辑不同。

**3. 计算页面上的指标**

| 指标 | 计算方式 |
|---|---|
| 查询数/秒 | 两次 `QUERIES` 差值 ÷ 采样间隔 |
| 连接数/秒 | 两次 `CONNECTIONS` 差值 ÷ 采样间隔 |
| 慢查询数/分钟 | 两次 `SLOW_QUERIES` 差值 ÷ 采样间隔，再换算为每分钟 |
| 失败连接数/秒 | 两次 `ABORTED_CONNECTS` 差值 ÷ 采样间隔 |
| 系统 CPU、用户 CPU、IOWAIT | 对应 CPU 时间增量 ÷ 总 CPU 时间增量 × 100% |
| 负载、复制延迟、可用内存、线程数 | 直接取最新快照 |
| 死锁 | 显示采样期间增量，并附带上一次计数 |

MySQL 指标主要来自全局状态；系统 CPU、负载、内存等由 SNMP 采集填入快照，不能单靠 JDBC 获取这些远端操作系统指标。

如果累计计数出现倒退，`diffAvgNoNegative()` 会尝试按“数据库重启后累计值 ÷ uptime”计算速率，避免显示负数。这属于一种重启后的近似处理。

**4. 状态颜色如何确定**

首先看**距上次成功访问的时间**。假设扫描周期为 `S` 秒：

| 情况 | 状态 |
|---|---|
| 尚未成功访问，且程序启动不超过 `S + 1` 秒 | Unknown |
| 尚未成功访问，已超过启动宽限时间 | Red |
| 距上次成功访问超过 `2S + 1` 秒 | Red |
| 超过 `S + 1` 秒，但未超过 `2S + 1` 秒 | Yellow |
| 仍在正常采样时间范围内 | Green |

然后检查性能阈值：

```text
IOWAIT 超限
或 系统 CPU + 用户 CPU 超限
或 LOAD AVG 超限
或 活跃线程数超限
```

任意一项超限，就把非 Red 状态设为 **Yellow**。

所以，这里的 **Red 主要表示采样访问不及时或一直无法访问；性能指标超限主要变为 Yellow**。复制延迟、慢查询等虽然显示在表格里，但没有直接参与这个控制器的颜色判定。

此外，还会附上最近检查时间、最近告警信息和扫描耗时。最近告警记录由其他采集/告警逻辑维护，这个控制器负责展示。

**5. 指定 `host` 的历史分支比较粗糙**

它查询最近 7 天的历史数据，但其中构造的 `connectCounter`、`slowCounter` 没有用于最终返回；慢查询累计还疑似误用了连接计数。不能把这部分视作已经完整实现的历史统计逻辑。

如果迁移到新版，值得保留的是：**后台定时采样、按实例保存前后快照、接口读取缓存汇总**。同时应将“采集是否正常”和“性能是否超限”分开表达，缺少采样时显示“暂无数据”，避免旧代码用 `0.00` 代替缺失值而造成误解。
